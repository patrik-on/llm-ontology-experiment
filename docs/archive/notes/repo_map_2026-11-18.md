# Mapa repa `patrik-on/llm-ontology-experiment`

Stav k 18. 11. 2026 (posledný commit `0f6adc6`, 18. 11. 2026). Iba čítanie, nič sa nemenilo.

## Účel
Experimentálna infraštruktúra k diplomovke *Využitie ontológií pri dotrénovaní LLM v softvérovom inžinierstve* (FMFI UK, vedúci doc. Polášek).
Porovnáva lokálny **Qwen2.5-Coder-7B** pri dvoch Java úlohách: **generovanie JUnit testov** a **refaktoring**.

Päť porovnávaných systémov (ramien):

| Rameno | Čo pridáva |
|---|---|
| `qwen_base` | nič, Ollama Q4_K_M |
| `ft_testing` / `ft_refactoring` | LoRA adaptér `b2_*_v2` cez HF/PEFT NF4 |
| `rag_single` | príklady z jednej Chroma kolekcie (`mixed` / `refactoring_db`) |
| `rag_multi` | `testing_db` + `refactoring_db`, RRF fusion |
| `skills` | baseline + presné bajty `SKILL.md` z externého repa `../si-context-eval` |

Adaptéry: `b1_shared_v2` (spoločný), `b2_testing_v2`, `b2_refactoring_v2` (špecializované). Zips sú mimo gitu, v repe sú len sha256 a manifest.

## Ako sa spúšťa
Všetko vo WSL z koreňa repa cez `.venv_wsl/bin/python`, s bežiacou Ollamou (`qwen2.5-coder:7b`, `bge-m3`), lokálnymi adaptérmi, existujúcim RAG indexom a Java nástrojmi (JDK 8/11/17, Maven, JaCoCo, RefactoringMiner).

```bash
python scripts/benchmarks/run_testing_matrix.py --run-id X --dry-run       # plán, bez zápisu
python scripts/benchmarks/run_testing_matrix.py --run-id X --freeze-only   # zmrazí prompty
python scripts/benchmarks/run_testing_matrix.py --run-id X                 # generovanie + hodnotenie
python scripts/benchmarks/run_testing_matrix.py --run-id X --report-only
python scripts/benchmarks/run_refactoring_matrix.py --run-id X --cases N|all [--prepare-pool|--prepare-only|--evaluate-only]
python -m pytest -q ; ruff check src scripts tests
```
Výstupy: `artifacts/evaluation/runs/<run-id>/`. Jeden pokus na bunku, 0 retries, 0 repairs, seed 42, temp 0, kontext 32768.

## Hodnotenie
- **Testing (Methods2Test, split EVAL):** model vypĺňa 2 telá testov do pevného scaffoldu (`testing-bodies-one-shot-v2`). Meria sa JSON/schéma, kompilácia, reálne JUnit vykonanie (2 repeats), volanie focal metódy, JaCoCo line/branch coverage. Default 5 prípadov × 5 ramien.
- **Refactoring:** pool 100 úloh (5 SWE-Refactor + 35 MaRV + 60 ML4Ref), Extract/Inline Method. RefactoringMiner musí nájsť presne zadanú operáciu; SWE navyše build + 2× regresné testy (Surefire XML).

## Stav
- Obe matice sú pripravené a zmrazené, ale **zatiaľ 0 modelových generovaní** v aktuálnych protokoloch (preparation runy: `testing-matrix-preparation-check-20261113`, `mixed-context-pool-v4-20261113`, `refactoring-context-v4-ready-20261114`).
- Historické výsledky: smoke `baseline_v1` / `baseline_v2` (Direct/RAG/MultiRAG, 72 behov, proxy metriky). Záver: RAG nepriniesol zlepšenie, proxy metriky boli saturované; preto vznikli súčasné vykonateľné matice.
- Podľa repa: 288 passed, 2 skipped. V čistom kontajneri bez extras: 273 passed, 49 failed (chýba `tree_sitter` a lokálne artefakty ako `artifacts/swe_overlap_audit_20261113/`), čiže ide o prostredie, nie o kód.

## Medzery voči zadaniu
- **Ontológie:** zadanie chce reprezentovať projektové a procesné znalosti ontológiami. V kóde ontológia nie je (len názov balíka). Procesný kontext je zatiaľ iba rameno `skills` (SKILL.md).
- **Kombinované poskytovanie znalostí** (projekt + proces, napr. skills+RAG alebo FT+RAG) sa explicitne netestuje.
- **Spoločný vs. špecializovaný FT:** adaptér `b1_shared_v2` existuje, ale aktuálne matice používajú len `b2_*`. Porovnanie shared/špecializovaný je v `main.tex`, na staršej proxy evaluácii.
- `main.tex` opisuje staršiu štruktúru (`data/`, `training/`) a 4 modely, nie súčasných 5 ramien.
- MultiRAG nemá skutočne odlišný druhý znalostný zdroj (konštatované v reportoch).
